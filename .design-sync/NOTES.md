# design-sync notes — EventHub UI kit

Repo-specific gotchas for future syncs. This is an **app repo** (`rest-express`),
not a standalone design-system library — the syncable surface is the shadcn/Radix
UI kit under `client/src/components/ui/`.

## Setup facts
- **Package shape, no dist.** Components are consumed as source by the Vite app.
  A real bundle entry is generated by `.design-sync/prebuild.mjs` (`cfg.buildCmd`)
  as `.design-sync/.cache/ds-entry.tsx` — `export *` from every `ui/*.tsx` except
  the excluded ones. Passed to the converter via `--entry`.
- **PKG_DIR = repo root.** The `--entry` path lives under `.design-sync/.cache/`,
  whose walk-up hits the repo-root `package.json` (name `rest-express`). `cfg.pkg`
  is a friendly override (`eventhub-ui`); `cfg.globalName` = `EventHubUI`.
- **`@/` path alias** resolves via `cfg.tsconfig` (`./tsconfig.json`,
  `@/* -> ./client/src/*`) through esbuild's tsconfig-paths plugin.
- **CSS is compiled by prebuild**, not scraped. `client/src/index.css` has
  `@tailwind` directives + custom `hover-elevate`/`toggle-elevate` @layer
  utilities (used by Button + Badge). `cfg.cssEntry` points at the compiled
  `.cache/ds-styles.css`; `.design-sync/tailwind.ds.config.ts` reuses the app
  theme and adds `previews/` to the content globs so preview-only utilities emit.

## Excluded / choices
- `LocationButton` — excluded (imports `@/hooks/useUserLocation`, app geolocation).
  Both dropped from the bundle entry (prebuild `EXCLUDE`) and null in
  componentSrcMap.
- `Toaster` (toaster.tsx) — not its own card; the `Toast` primitive (toast.tsx)
  is the listed component. Toaster is app wiring around `use-toast`.
- One primary component per file is listed in `componentSrcMap`; the bundle still
  exposes every compound part (CardHeader, DialogContent, TabsTrigger, …) on
  `window.EventHubUI` for composition in previews.

## Fonts
- Brand fonts load via a remote Google Fonts `@import` at the top of index.css:
  **Cormorant Garamond** (headings, `--font-heading`), **DM Sans** (body,
  `--font-sans`), **Damion** (logo, `--font-logo`). Expect `[FONT_REMOTE]`
  (informational) — they load at runtime, no `@font-face` shipped.
- NOTE: repo CLAUDE.md says "Playfair Display + DM Sans" but the actual heading
  font is **Cormorant Garamond**. Don't trust CLAUDE.md's font claim.

## Known render warns (triaged benign — re-syncs check against this list)
- `[FONT_REMOTE]` for DM Sans / Cormorant Garamond / Damion — expected; fonts
  load from the Google Fonts CDN `@import` (not vendored).

## Toast preview
- Toast's `ToastViewport` is `position: fixed` and `ToastClose` is absolutely
  positioned, so in grid/column card modes the content escapes the cell (blank
  or GRID_OVERFLOW-escape). Fixed two ways: the preview overrides the viewport
  with an inline `position: static`, and `cfg.overrides.Toast` uses
  `{cardMode:"single", primaryStory:"BookingConfirmed"}` (single cards are exempt
  from the grid-escape check). Both variants still exist as cells; the card shows
  the confirmation.

## Card presentation
- 9 components use `cardMode: "column"` (Card, Checkbox, RadioGroup, ScrollArea,
  Skeleton, Slider, Switch, Tabs, Textarea) because their stories are wider than
  the product grid cell — column gives one full-width story per row. Overlays
  (Dialog, Sheet, Popover, Tooltip, DropdownMenu, Select, Toast, Command,
  Calendar, Sidebar) use `cardMode: "single"` with a fixed viewport.

## Preview authoring gotchas (for future preview edits)
- **Arbitrary Tailwind classes** (e.g. `w-[380px]`) in preview .tsx files only
  compile if the prebuild recompiles ds-styles.css with `previews/` in content
  (it does on a full build). During a scoped `preview-rebuild` they can silently
  no-op — prefer inline styles for one-off widths/spacing in previews.
- **`--muted` is pure white** (`0 0% 100%`, index.css). `bg-muted` fills are
  invisible on the white capture background — put them on a tinted surface or
  use a border (Skeleton previews do this).

## Re-sync risks
- CSS fidelity depends on the compiled `.cache/ds-styles.css`. If Tailwind or the
  app theme changes, re-run `cfg.buildCmd` (the driver does this) so the compiled
  stylesheet + generated entry stay current.
- Fonts are remote (not vendored). If the DS pane shows fallback fonts, vendor
  the three families as woff2 via `cfg.extraFonts` instead of relying on the CDN.
- `.d.ts` prop contracts are synth-derived (no shipped types) and may be thin;
  strengthen specific components via `cfg.dtsPropsFor` if the design agent needs
  richer prop docs.
