Security Deposit Flow
Book a listing with a security deposit — deposit charge appears as a separate line item
Vendor files a damage claim dispute within the window — deposit is withheld pending resolution
Admin resolves dispute — deposit refunded to customer or released to vendor per decision
Cancellation Policy Edge Cases
Book and cancel within the full-refund window — full refund is issued
Book and cancel in a partial-refund window — correct partial amount is refunded
Book and cancel in the no-refund window — no refund is issued
Cancel a booking where a weather clause applies — verify clause affects the refund calculation
Confirm the cancellation policy snapshot on the booking matches the policy at the time of booking (not any later vendor edits)
Instant Book vs. Manual Confirm
Book an instant-book listing — booking immediately goes to confirmed, no vendor action needed
Book a non-instant-book listing — booking stays pending until vendor confirms
Payment Edge Cases
Use Stripe 3DS test card — flow handles requires_action state and completes authentication
Payment intent fails — booking does not enter confirmed state
Stripe webhook fires for payment event — booking status updates correctly
Duplicate / replayed Stripe webhook event — second event is deduplicated, no double processing

Do Not Mark Complete
Security Deposit — Automated Post-Dispute-Window Refund
The schema and checkout logic for security deposits are done (migration 0068), but the automated trigger that refunds the deposit 48 hours after the event (when no damage claim has been filed) has not yet been built. Manual testing of this auto-refund flow will fail. Do not mark this as passed.
